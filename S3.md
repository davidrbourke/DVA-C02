# S3

- Backup and storage
- Disaster recovery
- Archive
- Hybrid cloud storage - extend on-prem storage into the cloud
- Application hosting
- Media hosting
- Data lakes and big data analytics
- Delivering software updates
- Static website hosting

## Buckets

- Store **Objects** as files in **buckets** which are directories
- Bucket name must be globally unique
- Defined at region level
- Naming convention:
  - no uppercase
  - no underscore
  - 3-63 chars long
  - not an IP
  - start with lower case letter or number
  - must not start with xn--
  - must not end with -s3alias

### Objects

- Objects have a key, the key is the full path (prefix + directories + object name), e.g.: s3://my_bucket/my_dir_1/my_file.png
- Max object size is 5TB (increased to 50TB in 2025)
- Multi-part file upload where file/object is > 5GB
- Metadata - list of key/value pairs - set at object level
- Tags - unicode key/value pair - 10 max - set at object or bucket level
- Version ID (if versioning enabled)

## S3 Security

### User-based

- IAM Policies: which API calls are allowed for a specific user from IAM, e.g. Get\*, etc

### Resource-based

- Bucket policies: most common, bucket wide rules from the S3 console
- Object Access Control List (ACL): finer grain (can be disabled)
- Bucket Access Control List (ACL): bucket level control (can be disabled)

ACLs are legacy tech, and Bucket policies are recommended instead.

### IAM Principle Access rules

- The User IAM permissions allow it or, the resource policy allows it and there is no explicit deny.

### Encryption

Encrypt objects in S3 buckets using encryption keys

### Bucket Policy

```
{
    "Version": "2012-10-17,
    "Statement": [
        {
            "Sid": "PublicRead",
            "Effect": "Allow",
            "Principal": "*", // Allows all users, IAMs, etc
            "Action": [
                "s3:GetObject
            ],
            "Resource": [
                "arn:aws:s3:::examplebucket/*"
            ]
        }
    ]
}
```

The above is a public policy, the /\* allows Get access to all resources/objects in the S3 bucket. To allow a specific folder or file only, you could specify this in the Resource, e.g. "arn:aws:s3:::examplebucket/folder1/\*", or "arn:aws:s3:::examplebucket/file1.jpg"

Example use:

1. Public: Attach an **S3 Bucket Policy** to the S3 bucket to allow public access to the bucket.
2. User: Attach an **IAM policy** to an IAM User to allow the user to access the bucket.
3. EC2 Instance: Create an **IAM Role** for the EC2 with correct **IAM Permissions** so the instance can access the bucket.
4. Cross account access: IAM User is in another AWS Account, create an **S3 Bucket Policy** that allows cross account access for the specific IAM User and attach it to the S3 Bucket.

#### Bucket settings to block public access

These rules override the Bucket policies to protect accidental exposure of data by lower rules. E.g. if a bucket should never be public, leave the rules on, they can be set at S3 bucket or account level:

- Block public access to buckets and objects granted through **new** access control lists
- Block public access to buckets and objects granted through **any** access control lists
- Block public access to buckets and objects granted through **new** public bucket or access point policies
- Block public and **cross-account access** to buckets and objects through **any** public bucket or access point policies

### Demo: Allowing public access

1. Unblock _Block public access (bucket settings)_ rules (see the 4 above)
2. Edit the bucket policy for the S3 bucket
   - Can use policy generator
   - Create a policy similar to one in example above.

## Static website hosting

1. Ensure you have set all the content to publicly readable (Unblock block public access, and allow access)
2. Need to enable the option **Static website hosting**
3. Specify the name of, and upload an index.html.
4. Optional: Can specify a default error.html
5. Upload the index.html (or whatever it's called) and the required static content.
6. A static website content url will be generated that you can use to access the website - this will use the index.html as the root.

## Versioning

- Versioning is enabled at the bucket level - not enabled by default.
- When enabled, re-uploading a new copy of an existing file, increments the version.
- Files uploaded before enabling versioning, the version is 'null'
- Protects against unwanted deletes, as you can roll back to the previous version. When enabled:
  - If you delete an entire object (not specific version), a **delete marker** is added. To restore the object, delete the delete-marker.
  - If you delete a specific object version, this **permanently deletes** the specific version, and the previous version becomes the current version.
- Suspending versioning does not delete the previous existing versions.

## Replication

- Cross Region Replication
  - Replicating to an S3 Bucket in another region
  - Use Cases: compliance, lower latency.
- Same Region Replication
  - Replication within the same region
  - Use Cases: log aggregation, replication from prod to test.
- Copying is asynchronous
- IAM permissions to S3 must be setup.
- Versioning must be enabled in both source and replication S3 buckets.
- Only new objects are replicated once replication is enabled
  - S3 batch replication feature must be used to copy across existing & failed objects
- Deletes:
  - Can replicate delete markers from source to replication (needs to be enabled)
  - Specific version deletes are not replicated

## Storage Durability

Represents how many times an object is going to be lost. 1 object per 10 million over 10 years (99.999999999%).
This is the same for all storage classes.

## Storage Availability

Measure how available the service is, e.g. the amount of time per year the service is unavailable.
Varies by Storage class.

## Lifecycle rules

Lifecycle rules can be setup to automatically move objects between the tiers based on rules.

- Transition Actions
  - E.g. move objects from Standard to Standard IA 60 days after creation
  - Move to Glacier archiving after 6 months
- Expiration Actions
  - Configure objects to expire (delete) after time
  - E.g. Delete log file after 365 days
  - Can delete 'versions' of objects if versioning is enabled
  - Can delete incomplete multi-part uploads (if over a certain amount of time)
- Rules can be configured for entire buckets or a specific paths, or specific tags.

### S3 Analytics

This will run on Standard and Standard IA storage classes (only) and help to make decisions about when to setup lifecycle rules to move objects to other storage classes.

### Demo

1. In S3 Buckets > Management > Create lifecycle rule
2. Enter rule name
3. Choose scope of objects:

- All objects in scope
- Custom filters for objects in scope

4. Lifecycle rules actions

- Move current versions of objects between storage classes
  - Add various Transitions: target storage class and number of days after object creation
  - E.g. Move to Standard IA after 30 days, move to Glacier after 90 days, etc
- Move noncurrent versions of objects between storage classes
  - Add various Transitions: target class, days after objects become noncurrent, number of newer versions to retain (optional)
- Expire current versions of objects
  - Add number of days after object creation
  - Deletes the object
- Permanently delete noncurrent versions of objects
  - Add days after objects become noncurrent, number of newer versions to retain (optional)
- Delete expired object delete markers on incomplete multipart uploads

## S3 Event Notifications

- These are events that are triggered based on actions in S3, e.g. a file is uploaded
- Can filter for specific object types, e.g. .jpg
- No limit to the number of events you can setup
- Event notification can take a 1min+
- Example: Image is uploaded, you want an event triggered to create a thumbnail. The event can be sent to various AWS Services
- The Event message will include data about the object, e.g., the action type, the name of the object, etc.
- Service events can go directly to:
  - Lambda
  - SQS
  - SNS
- IAM Permissions are needed **on the target service** for S3 to send the event
  - SNS Example: an SNS Resource (Access) Policy needs to be setup on the SNS resource to allow the S3 bucket to send the event notifications.
  - SQS: SQS Resource Access Policy
  - Lambda Resource Policy
- **Amazon Event Bridge**:
  - By default **all** event notifications go into an **Amazon Event Bridge**
  - From Amazon Event Bridge, the events can be forwarded to 18 other destination AWS services (so not limited ot just SQS, SNS, Lambda).
- Demo
  - On S3 bucket, there are 2 options:
    - 1. Enable Event Bridge
    - 2. Create an event notification (for SNS, SQS, Lambda).
      - You can filter based on event types, and object types, e.g. s3:ObjectCreatedPut or all events.
      - Choose destination - it must be created, and IAM permission setup, by enhancing the access policy on the target resource.
      - If the access permission is not setup, you will be blocked from creating the event notification in the AWS Console.

### Example of the Policy on the SQS

```
{
  "Version": "2012-10-17",

        "ArnEquals": {
          "aws:SourceArn": "arn:aws:s3:::my-s3-bucket"
        }
      }

```

## S3 Baseline Performance

- A **prefix** is any 'sub-directory' in the bucket path, e.g. bucket-name/**folder1**/file1.png, bucket-name/**folder2**/file2.png.
- Spliting an S3 bucket into prefixes helps to get more performance out of the bucket.
- Latency: 100-200ms
- 3,500 PUT/COPY/POST/DELETE per **prefix** per second
- 5,500 GET/HEAD request per **prefix** per second
- No limits to the number of prefixes in a bucket.

### Multipart upload

- Required for file > 5GB, must be split to a minimum of 5GB parts
- Recommended for files > 100MB.
- When using multipart upload, a file is split into parts and uploaded in parallel, S3 combines the parts into a single file.

### S3 Transfer Acceleration

Instead of uploading the entire file over the public internet, Edge locations can be used, this is the nearest geographical Edge location where the file is sent to it over the public internet. Then the Edge location transfers the file to the S3 bucket over the AWS network which is faster.

### S3 Byte-Range Fetches

- For larger files, you can specify to download the file in separate ranges of bytes, and the separate blocks of bytes are downloaded in parallel.
- You can also request just part of a file, e.g. if you know a specific section like the first few bytes contain the information you need, so you don't need to download the entire file.

### S3 Objects Tags & Metadata

- Metadata
  - Name-value (key-value) pairs
  - Amazon assign some metadata
  - Stored in lower case
  - Custom user defined metadata can be defined using "x-amz-meta-" prefixed names, defined when uploading the object.
  - Metdata can be retrieved along with the object
- Object Tags
  - Key-value pairs
  - Useful for fine grained permissions, e.g., only access images with specific tags.
  - Can be used in S3 Analytics to group by tags, etc.
- You cannot search objects by metadata or tags, you would need to track an index separately, e.g. in your own database.
