- Disaster recovery
- Archive
- Hybrid cloud storage - extend on-prem storage into the cloud
- Application hosting
- Media hosting
- Data lakes and big data analytics
- Delivering software updates
- Static website hosting

## Buckets

- Store **Objects** as files in **buckets** which are directories
- Bucket name must be globally unique
- Defined at region level
- Naming convention:
  - no uppercase
  - no underscore
  - 3-63 chars long
  - not an IP
  - start with lower case letter or number
  - must not start with xn--
  - must not end with -s3alias

### Objects

- Objects have a key, the key is the full path (prefix + directories + object name), e.g.: s3://my_bucket/my_dir_1/my_file.png
- Max object size is 5TB
- Multi-part file upload where file/object is > 5GB
- Metadata - list of key/value pairs - set at object let
- Tags - unicode key/value pair - 10 max - set at object or bucket level
- Version ID (if enabled)

## S3 Security

### User-based

- IAM Policies: which API calls are allowed for a specific user from IAM, e.g. Get\*, etc

### Resource-based

- Bucket policies: most common, bucket wide rules from the S3 console
- Object Access Control List (ACL): finer grain (can be disabled)
- Bucket Access Control List (ACL): bucket level control (can be disabled)

### IAM Principle Access rules

- The User IAM permissions allow it or, the resource policy allows it and there is not explict deny.

### Encryption

Encrypt objects in S3 buckets using encryption keys

### Bucket Policy

```
{
    "Version": "2012-10-17,
    "Statement": [
        {
            "Sid": "PublicRead",
            "Effect": "Allow",
            "Principal": "*", // Allows all users, IAMs, etc
            "Action": [
                "s3:GetObject
            ],
            "Resource": [
                "arn:aws:s3:::examplebucket/*"
            ]
        }
    ]
}
```

The above is a public policy, the /\* allow Get access to all resources/objects in the S3 bucket. To allow a specific folder or file only, you could specify this in the Resource, e.g. "arn:aws:s3:::examplebucket/folder1/\*", or "arn:aws:s3:::examplebucket/file1.jpg"

Example use:

1. Public: Attach an **S3 Bucket Policy** to the S3 bucket to allow public access to the bucket.
2. User: Attach an **IAM policy** to an IAM User to allow the user to access the bucket.
3. EC2 Instance: Create an **IAM Role** for the EC2 with correct **IAM Permissions** so the instance can access the bucket.
4. Cross account access: IAM User is in another AWS Account, create an **S3 Bucket Policy** that allows cross account access for the specific IAM User and attach it to the S3 Bucket.

#### Bucket settings to block public access

These rules override the Bucket policies to protect accidental exposure of data by lower rules. E.g. if a bucket should never be public, leave the rules on, they can be set at S3 bucket or account level:

- Block public access to buckets and objects granted through **new** access control lists
- Block public access to buckets and objects granted through **any** access control lists
- Block public access to buckets and objects granted through **new** public bucket or access point policies
- Block public and **cross-account access** to buckets and objects through **any** public bucket or access point policies

### Demo: Allowing public access

1. Unblock _Block public access (bucket settings)_ rules (see the 4 above)
2. Edit the bucket policy for the S3 bucket
